# Security policy

## Supported versions

Security fixes are provided for the latest production release. Users should
upgrade to the newest published version before reporting an issue.

## Reporting a vulnerability

Do not publish an exploitable file or detailed reproduction in a public issue.
Contact the project maintainer privately through the security-reporting channel
of the repository hosting this source. Include the affected version, operating
system, a minimal malicious or malformed input when safe, and the observed
impact. The maintainer should acknowledge a report within seven days and
coordinate disclosure after a fix is available.

ATE processes untrusted TLK, 2DA, and ITP files. Reports involving crashes,
resource exhaustion, path replacement, converter invocation, or malformed-file
acceptance are security relevant.
